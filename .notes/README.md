# Notes

This folder is the shared memory for the repo.

Use it for:

- codebase overviews
- architecture decisions
- system decisions
- implementation tradeoffs
- anything the team needs to remember later

## How to write notes

- One file per topic or decision.
- Use a dated filename when the note is a decision record, for example `2026-07-26-backend-structure.md`.
- Keep each note short and explicit.
- Include the context, the decision, the reason, and any follow-ups.

## Suggested note format

```md
# Title

## Context
Why this came up.

## Decision
What we chose.

## Reasoning
Why this was the right choice.

## Follow-up
Anything that still needs to happen.
```
